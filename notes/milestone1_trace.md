# Milestone 1: the path a submission takes

## 1. The path, from arriving to the label a reader sees

| # | Where | What it adds |
|---|---|---|
| 1 | `POST /submit` (`app.py::submit`) | Receives JSON with `text` and `creator_id`. |
| 2 | Input check (`app.py::_check_submission`) | Refuses anything malformed with a 4xx and a reason (no `text`, empty, not a string, over 20,000 characters, no `creator_id`, body not a JSON object). Each refusal is logged. Nothing malformed reaches a model. |
| 3 | Signal one (`detector.py::model_signal`) | A 0–1 score for how predictable the text is to gpt2. Higher means more AI-like. |
| 4 | Signal two (`stylometry.py::style_signal`) | A 0–1 score for the shape of the text: sentence-length spread, vocabulary variety, expressive punctuation. Higher means more AI-like. |
| 5 | Combine (`scoring.py::combine_signals`) | One 0–1 score: 0.6 × model + 0.4 × style, capped at 0.69 if either signal leans human. |
| 6 | Label (`scoring.py::score_to_label`) | `human` below 0.45, `unsure` 0.45–0.70, `ai` above 0.70, plus the sentence a reader sees. Under 40 words is always `unsure`. |
| 7 | Log and answer (`audit.py::log_decision`) | Writes the decision with both signal scores to `logs/audit.jsonl`, and returns a `content_id` the writer needs if they want to appeal. |

## 2. The two signals

**Signal one: the model signal (`detector.py`)**
- *Measures:* how predictable the text is to a language model (perplexity).
- *Why it might differ:* a model writes by picking likely next words, so model
  text is text a model finds easy to predict. Human writing takes odd turns.
- *What it can't see:* who wrote it. It rewards common words in ordinary
  sentences, so plain human writing reads as machine-like: second-language
  writers, younger writers, anyone writing simply on purpose. Famous text the
  model has seen in training also reads as predictable.

**Signal two: the style signal (`stylometry.py`)**
- *Measures:* the text as text: how much sentence length varies, how varied
  the vocabulary is, and how much expressive punctuation it uses.
- *Why it might differ:* generated prose marches in even, mid-length sentences
  with few dashes, brackets, questions or quotes. People's writing is lumpier.
- *What it can't see:* what the text says. Anything that changes the shape
  without changing the meaning moves it: breaking sentences up, adding dashes,
  a quotation, a question. In `samples/`, the lightly edited version of the
  time-management text scores 0.34 on style and is labelled human; the
  unedited version scores 0.62.

## 3. Tracing the false positive

A writer who learned English as a second language posts a short piece about
their dog. They write in short, even sentences with words they're sure of:
"Dogs are good pets. They are loyal and they love their owners. A dog needs
food, water, and a safe place to sleep..."

- **What score do they get?** That exact style of paragraph is in the
  calibration set (`ai_5`; it happens to be AI-generated, but a person could
  write it word for word). It scores model 0.886, style 0.680, combined
  0.804. Both signals lean AI, so the veto doesn't help.
- **What does the label say to them?** "This piece shows strong signs of being
  generated by AI: both of our checks point that way. Automated checks can be
  wrong. If you wrote this yourself, you can appeal, and a person will review
  it."
- **What can they do about it?** `POST /appeal` with the `content_id` from
  their submission and a sentence on why. The item moves to `under_review`,
  their reasoning is logged beside the original decision (which isn't
  overwritten), and they get a confirmation saying it's marked under review,
  not as AI-generated.

What this trace decided: the AI line sits at 0.70, well above the highest
human calibration passage (0.538), and either signal can veto an AI label.
That still doesn't save this writer. The appeal is the only protection they
have, which is why every appeal has to be recorded (criterion 4).

## 4. The endpoint contracts

### `POST /submit`

**In** (JSON object, `Content-Type: application/json`)

| Field | Type | Rules |
|---|---|---|
| `text` | string | Required. Not empty or whitespace. At most 20,000 characters. |
| `creator_id` | string | Required. Not empty. |

**Out: 200**

| Field | Type | Meaning |
|---|---|---|
| `content_id` | string | 12 hex characters. Needed to appeal. |
| `guess` | string | `"human"`, `"unsure"` or `"ai"`. |
| `confidence` | number 0–1 | The combined score. 0 = confidently human, 1 = confidently AI. |
| `label` | string | The sentence shown to a reader. |
| `model_score` | number 0–1 | Signal one. Higher = more AI-like. |
| `style_score` | number 0–1 | Signal two. Higher = more AI-like. |
| `status` | string | Always `"decided"` on a new submission. |

**Out: errors**, always `{"error": "<code>", "message": "<plain English>"}`

| Status | `error` | When |
|---|---|---|
| 400 | `invalid_body` | Body isn't a JSON object. |
| 400 | `missing_text` / `invalid_text` / `empty_text` | `text` is missing or null / not a string / blank. |
| 400 | `missing_creator_id` | `creator_id` missing or blank. |
| 400 | `too_short` | Under 3 model tokens: nothing to score. |
| 413 | `text_too_long` | Over 20,000 characters. |
| 503 | `detector_unavailable` | The model couldn't load. |

### `POST /appeal`

**In** (JSON object)

| Field | Type | Rules |
|---|---|---|
| `content_id` | string | Required. Must be one `/submit` returned. |
| `reasoning` | string | Required. Not blank. At most 5,000 characters. |
| `creator_id` | string | Optional. If given, it must match whoever submitted the piece. |

**Out: 200**

| Field | Type | Meaning |
|---|---|---|
| `content_id` | string | Echoed back. |
| `status` | string | `"under_review"`. |
| `appeal_recorded_at` | string | UTC timestamp of the appeal entry. |
| `previous_guess` | string | What the system had said. |
| `message` | string | Confirmation for the writer. |

**Out: errors**, same shape as `/submit`

| Status | `error` | When |
|---|---|---|
| 400 | `invalid_body` / `missing_content_id` / `missing_reasoning` | Malformed request. |
| 403 | `not_your_submission` | `creator_id` given and doesn't match the submitter. |
| 404 | `unknown_content_id` | No submission with that id. Nothing is recorded as an appeal. |
| 413 | `reasoning_too_long` | Over 5,000 characters. |

Every refusal on either endpoint is written to the audit log as a `rejected`
entry.
